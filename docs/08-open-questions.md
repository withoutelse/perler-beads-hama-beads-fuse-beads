# 已确认事项与剩余风险

## 已确认

1. **用户体系**：只面向单人自用。不做登录、多用户、权限、配额、分享链接和计费。
2. **Tripo 输出**：使用 GLB；任务创建后轮询，成功后下载模型。
3. **豆规格**：5mm 标准豆使用 29×29 板；2.6mm 迷你豆使用 57×57 板。
4. **色卡**：默认 Perler Standard，色号可配置。
5. **颜色容差**：默认 `ΔE = 6.0`，后续允许在 0–15 范围内调整。
6. **双面有孔工艺**：所有板件统一采用双面有孔烫法，不区分轻烫区/重烫区；只输出结构图纸和孔保留标记，不承诺具体熨烫温度/时间。
7. **装配可达性**：要求唯一汇点 + 顶部开口；封顶件从上往下压合。
8. **物理公差**：槽比舌宽 1 格，后续用真实打印/熨烫结果校准。
9. **PDF 规格**：A4、1:1、中文、自动分页。
10. **部署环境**：本地 Windows 优先，同时保持 Docker 兼容。
11. **3D 预览**：M1 只做 GLB 产物和作业状态；体素/切片预览从 M2 起逐步增加。
12. **失败兜底**：局部点胶必须显式确认并生成风险说明，不能静默降级。

## 剩余风险

1. **真实 Tripo 接口**：当前客户端按 `upload -> /task -> /task/{id}` 和 `data.file_token / task_id / status / progress / output.model` 实现，尚未用真实 API Key 验证。若官方字段不同，只需调整 `apps/api/app/pipeline/adapters/tripo.py`，不要改领域路线。
2. **模型版本**：默认 `v2.5-20250123`，需要账号实际可用版本确认。
3. **物理校准**：熨烫膨胀、豆径公差、插舌间隙目前是经验默认值，必须用真实制作结果回归。
4. **依赖环境**：后端虚拟环境、前端 `node_modules` 和锁文件已就绪；240 项后端测试、`ruff`、`mypy`、`compileall` 和前端构建已通过。真实 Tripo 账号联调和 Docker 镜像构建仍未验证。
5. **生产化**：M8 的 PostgreSQL、S3/MinIO、多 worker、鉴权、配额和监控不属于单人自用首版范围。
6. **薄壁黄金样例**：`fixtures/m3-decomposition.json` 的 5×5×3 空心方管壁厚只有 1 格，无法容纳“2 格承力舌 + 1 格槽余量”的贯穿槽；M4-T1 仍会为环片/围板接触生成 2×3 承力候选描述符，M4-T2 已将其全部判为 `WALL_TOO_THIN`。7×7×3 环的壁厚为 2 格，同样全部不可制造；11×11×1 厚壁环的 4 个候选全部生成完整布尔，11×11×3 厚壁环生成 12 个完整布尔并跳过 `J01`、`J06`、`J15`、`J16` 四个薄壁候选。M4-T3 已在这些完整布尔上验证槽口到板边界的槽腔平面可达性：11×11×1 的 4 个和 11×11×3 的 12 个全部可达。5×5×3 样例继续作为分解/接触图黄金样例，不应被当作可组装成品；同边间距与防撕裂属于 M4-T4，双面有孔烫法标记与孔保留校验属于 M4-T5。
